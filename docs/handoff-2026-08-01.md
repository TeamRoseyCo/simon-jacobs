### The blog is now a CMS, not a TypeScript file

This is the big structural change and it invalidates older docs that say
"Blog = `src/lib/posts.ts` (TS data, NOT a DB)".

- Content lives in the **`blog_posts`** table, Supabase project
  **`stkdstczvulyoeyokubj` (SimonJacobs)**, the same project as leads.
- `src/lib/posts.ts` is now a **server-only** data layer exposing async
  `getAllPosts()` and `getPost(slug)`. Never import it from a `"use client"`
  file. That is why `ScorecardForm` receives its 3 featured posts as a prop.
- **`/admin/blog`** is the editor, behind the existing admin login. List,
  create, edit, delete. API routes are `src/app/api/admin/blog/`.
- Admin writes call `revalidatePath` on `/`, `/blog`, `/scorecard`, the post
  itself, and `/sitemap.xml`, so publishing is live immediately without a
  deploy.
- All 20 posts migrated and verified. The migration script was one-off and has
  been deleted; the original array is in git history at `11d3181`.

**Trap for the next session:** `src/app/admin/ui.tsx` is a `"use client"`
module, so its exports are client references. Calling `pageWrap()` or spreading
`headerRow` from a **server** component throws at runtime and returns a 500,
and the production build will not catch it. Admin server pages must do auth and
data fetching only, and all chrome belongs in the client component. This
already bit once (`cadc46b`).
