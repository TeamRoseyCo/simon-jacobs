# Website contribution guidance

Keep application code focused on behavior and structure. Do not add editorial, design-history, copy-rationale, stakeholder, or change-log comments to source files.

Put durable project context in `docs/` instead. Use a clearly named Markdown document for the relevant subject, and link to it from existing documentation where useful. Code comments are acceptable only when they are short and necessary to explain a non-obvious technical constraint, security safeguard, or integration behavior that cannot be made clear by the code itself.
